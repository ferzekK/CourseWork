# Курсова робота

Проєкт розв'язує задачу планування доставки замовлень контейнеровозами.

Для кожного замовлення задано:

- `id` - номер замовлення;
- `t_i` - час доставки в один бік;
- `d_i` - директивний строк доставки;
- `w_i` - вага або пріоритет замовлення.

Також задано:

- `n` - кількість замовлень;
- `m` - кількість контейнеровозів.

Після виконання замовлення контейнеровоз повертається назад, тому повний час зайнятості для одного замовлення:

```text
2 * t_i
```

Час завершення доставки:

```text
C_i = S_i + t_i
```

Замовлення вважається запізнілим, якщо:

```text
C_i > d_i
```

Цільова функція:

```text
F = сумарна вага запізнілих замовлень / сумарна вага всіх замовлень
```

Чим менше значення `F`, тим кращий розклад.

## Основна ідея коду

Класи використовуються тільки для моделей даних у `Models/models.py`:

- `Order`;
- `ScheduleResult`;
- `Schedule`.

Алгоритми реалізовані звичайними функціями.

У `Algorithm/greedy_algorithm.py`:

- `solve_greedy(orders, m)`;
- `solve_greedy_by_rule(orders, m, rule)`;
- `get_sort_key(order, rule)`.

У `Algorithm/local_search_algorithm.py`:

- `solve_local_search(start_schedule, orders, max_iterations)`;
- `calculate_result(schedule, orders)`;
- `generate_neighbors(schedule)`;
- `swap_orders(schedule, truck1, pos1, truck2, pos2)`;
- `move_order(schedule, truck1, pos1, truck2)`.

## Жадібний алгоритм

Жадібний алгоритм:

1. Рахує розклад за правилом `SPTu`.
2. Рахує розклад за правилом `SLACK_OVER_W`.
3. Порівнює значення цільової функції `F`.
4. Повертає той розклад, де `F` менше.

Правила сортування:

```text
SPTu: t_i / w_i
SLACK_OVER_W: (d_i - t_i) / w_i
```

Функція `solve_greedy(orders, m)` повертає найкращий результат серед цих двох правил.
У консольному виводі також показуються значення `F` для обох правил, щоб їх можна було порівняти.

## Локальний пошук

Локальний пошук покращує розклад, отриманий жадібним алгоритмом.

Для цього створюються сусідні розклади за допомогою:

- перестановки двох замовлень;
- переміщення замовлення з одного контейнеровоза на інший.

Якщо знайдено розклад з меншим значенням `F`, він стає поточним.
Після завершення локального пошуку програма виводить причину завершення: неможливо покращити розклад або досягнуто максимальну кількість ітерацій.
